# 插件接口规范

插件是 `neo-runner` 扩展任务能力的标准入口。为保证平台可维护性，所有插件应遵循统一、稳定的执行契约。

## 执行契约

- 输入：标准化的 `TaskSpec`（由配置加载与计划阶段产出）。
- 输出：统一的 `RunResult`（包含成功状态、统计信息与可扩展元数据）。
- 事件：通过 `eventbus` 发布生命周期事件（如 `task_started`、`task_finished`）。

## 设计原则

1. 稳定优先：插件对外行为稳定，避免频繁破坏性改动。
2. 错误统一：插件错误应映射到核心错误模型，便于上层处理和汇总。
3. 可观测性：关键执行节点需产出事件，支持日志、指标与审计。

## 内置与扩展

当前内置插件目录为：`shell`、`http`、`sql`（预留）。后续新增插件建议保持同构目录结构与命名规范，确保团队协作与自动化工具链可持续演进。
